# 0.2.2 开发者服务准备

此版补齐定位前的开发者映像（DDI）查询、下载、挂载和复查。未连接或操作真机。构建及自动检查结果以随包内审报告为准。

## 使用行为

- 点击开始模拟：先检查本设备远程配对及开发服务。已挂载时直接继续；仅在设备明确报告缺少映像时联网下载、校验并挂载，随后再次查询确认。无法读取状态时不当作“缺少映像”。准备失败不提交新位置，也不要求重新登录 Apple 账号。
- 设置新增“准备定位开发服务”，可提前准备，不发送位置。普通“检查定位连接”只检查，不下载或挂载。
- 清除定位在必要时同样先准备服务，只有底层清除成功才移除“可能遗留模拟”记录。准备或清除失败保留该记录。
- 首次下载约 17 MB，文件在设备本地缓存，采用固定提交、精确大小和 SHA-256 校验；下载写磁盘，校验分块执行，缓存损坏会重新下载。有效缓存不会重复下载，已挂载时不读缓存。
- 准备期间请保持前台。进入后台会取消下载和后续提交。同步原生挂载不能安全强行中断，需等调用返回；此时仍显示忙碌，不把超时当作成功。映像安装可能需要连接 Apple 的个性化服务；不使用用户 Apple 密码，也不上传配对或签名私钥。
- 定位与续签共用“忙碌”锁。DDI 使用当前定位隧道，不另启 minimuxer，避免并发连接和账户依赖。

## 来源与系统分支

定位准备流程参考固定的 [StikDebug 3.1.13](https://github.com/StikDebug/StikDebug/tree/4bdfc92aa7cebd7a534f1e1ef56415f5727402de)：DeveloperDiskImageService.swift、IdeviceFFIBridge.swift、mountDDI.swift、TunnelManager.swift。

上游按系统版本选择：低于 26.4 使用 Personalized，26.4 及以后使用 Cryptex。该分支只是上游选择逻辑，不能证明未来系统或当前设备已经兼容。定位仍要求本设备远程配对及 LocalDevVPN。

映像源固定为 [DeveloperDiskImage 提交 6eae353](https://github.com/doronz88/DeveloperDiskImage/tree/6eae353ae694bda1c421d4a3eee5459ae59c99a1/PersonalizedImages)，8 个文件的大小、URL 和 SHA-256 在 upstream-lock.json 及应用资源 AssistantDDIManifest.json。映像为 Apple 开发资源，本仓库只提供固定下载清单，不将映像二进制打入 IPA。

## 自动验证范围

新增分支/清单/缓存/损坏/HTTP 错误/取消测试，以及对实际 AssistantNative.swift 的 Personalized/Cryptex C 接口故障注入：检查状态不可达、空句柄、开发者模式关闭、文件/挂载失败、挂载后未就绪、重复准备和资源释放。原有 9 项检查继续运行。

这些检查使用模拟设备接口，不能验证真实 Rust 库的网络行为、Apple 映像个性化服务、系统允许挂载、定位后台维持、真实位置恢复或自身续签。此前 Apple -80045/-22421/-90010 没有通过真机验证解决。未安排安装或真机验收。
