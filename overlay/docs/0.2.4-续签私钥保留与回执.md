# 0.2.4：保留已导入的私钥，并记录自身续签结果

0.2.3 真机操作后发现：用户先导入完整 p12，再首次进入签名验证时，延迟启动签名数据库仍会调用上游 MaintenanceManager。固定上游的第一个历史维护任务会 clearAll 钥匙串并退出账号，删除刚导入的私钥；维护计数文件不存在时也会从该任务开始。这是合并流程中的遗漏，不能归因于用户切换 App Store/iCloud 账号。

0.2.4（8）移除了定位助手签名初始化对上游历史维护任务的调用，只启动数据库并处理自身重新安装的记录。签名初始化不再清空账号、证书、配对或收藏；保留不自动撤销已有证书的策略。导入成功后立即重新读取私钥状态，读取失败与确实没有私钥分别显示。

旧版本续签状态只在内存中保存，重开后又显示“尚未验证”；新版在本设备保存脱敏的最近操作结果，区分已导入证书、上次账号验证、续签已开始、成功回执、失败与结果未确认。保存的登录凭据与历史验证记录均不表示 Apple 当前会话有效。

另一个显示问题：SideStore 快速续签安装设备上的描述文件，不一定重写 App 内 embedded.mobileprovision，安装包中的到期日期因此可能不变。新版分别显示“安装包内到期时间”和“最近续签回执”；只有设备安装流程返回成功且取得有效到期时间时记录成功回执。进程中断、缺少到期信息、只登录或只下载认证配置，均不产生新的成功回执。历史回执不能证明证书后来没有被撤销。

新增测试使用生产代码中的 prepareDatabase 方法和固定上游 MaintenanceManager，先插回原调用，必须复现刚导入的私钥被删除，再对实际修复后的方法验证首次登录、重复调用、数据库失败与重试、协调器重新创建，以及没有 App Group 计数文件的情形。另测历史回执跨重载保留、失败后不推进成功时间、中断不误报成功。原有定位、下载、认证策略和依赖检查仍需全部通过。

安装：使用原签名账号覆盖安装，保留现有 App、配对和导出的完整 p12。若旧版已删除本地私钥，代码修复无法凭空恢复；可从用户已经保留的 p12 重新导入一次，然后验证 Apple 签名账号及自身刷新。不要为了本次修复撤销或重建证书。

本版真实设备续签仍需单独验证，编译或模拟存储测试不等于 Apple/设备端已通过。
