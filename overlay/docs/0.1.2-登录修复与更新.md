# 0.1.2 登录修复与更新

本版本针对 Apple 登录返回 -80045 的近期兼容问题；真机登录及自身续签结果仍须逐设备验证，不保证 Apple 服务一直可用。

## 更新

1. 保留旧 App。电脑 iloader 使用该设备原来的签名账号，选择 Import IPA，导入本版 LocationAssistant.ipa，覆盖安装。保持原签名账号和应用标识才能访问原数据，安装失败时不要先删除旧 App。
2. 打开定位助手，进入设置，确认“登录服务”为“自动匹配（推荐）”。点击“检查登录服务”；此检查只验证认证服务配置可获取，不代表 Apple 账号已登录或续签成功。
3. 返回续签页，登录原签名账号。若 Apple 已将验证码推送到受信任设备，直接输入该验证码。
4. 续签时连接 Wi-Fi 和 LocalDevVPN，点击刷新自身签名。重新打开，核对实际到期时间确实更新；再检查配对和收藏。
5. iPhone、iPad 分别操作并记录结果。共享签名账号需要同一有效证书和私钥；配对文件仍各自独立。

## 遇到错误

- -80045：保留提示。确认自动匹配，检查登录服务后再登录；不要为此撤销证书。
- -45061：设置→重建登录认证缓存→重试。只清除兼容登录服务的缓存，不删除签名证书、Apple 密码、配对或收藏。
- 认证服务不可连接：需要能访问该 HTTPS 服务的互联网连接；LocalDevVPN 仅提供本机通道，不提供外网代理能力。
- 缺少私钥：这是与 -80045 不同的问题。先确认使用原签名账号和证书，保留 App，通过完整证书导入恢复，勿自动重新申请或撤销证书。
- 续签失败：设置→脱敏诊断信息，查看最近失败阶段与分类；账号登录成功并不代表本设备连接和续签通过。

## 实现与来源

- 保留 SideStore 和 SideSign 现有固定版本，只覆盖 SideSign 的 Authentication.swift。文件逐字取自已合入的修复提交 752d1ef602aa792a432ffa1e71646dc1ecf7363c，并记录 SHA-256；其父版本与本项目锁定版本的对应文件一致。
- 从固定 HTTPS 认证服务的 /v3/client_info 获取客户端信息，不硬编码社区临时 Android 客户端字符串。采用 iloader 近期修复中按服务匹配客户端信息的方式，服务器分别维护设备认证状态。
- Apple 账号密码仍由登录库提交给 Apple；认证辅助服务只参与既有 anisette 流程，不接收签名证书或配对文件。GitHub 构建不接收这些设备数据。
- 新凭据使用不同步的本设备钥匙串。升级时复制当前可读取的旧同步项目，不删除或修改同步原件，避免影响另一台设备。若旧同步项目在迁移时不可访问，明确停止并显示钥匙串错误。
- 证书保存后读回、解密并检查私钥和序列号；写入失败恢复原存储并报告错误。证书验证忽略十六进制序列号字母大小写。
