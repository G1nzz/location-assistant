# 定位助手 0.2.1（5）内部审查

基于 0.2.0（4）继续审查；本轮不安排真机测试。审查覆盖自定义界面、状态流、SideStore 登录/证书/安装调用、固定 StikDebug FFI 接口、依赖还原与 IPA 打包。保留原版源码及 IPA。

## 已发现并在代码中修复

| 问题 | 触发条件与影响 | 修复与检查方式 |
| --- | --- | --- |
| 旧 URL 导出入口仍可达 | 外部网页或 App 调用 pairing/certificate 链接，可进入上游导出流程；其中配对回调不要求确认 | 封闭旧 URLHandler、AppDelegate 和 SceneDelegate 的导入/导出入口；拒绝链接的 Swift 回归测试 |
| 验证账号过早要求设备连接 | 尚未验证 Apple 账号就启动 VPN/配对流程，报错来源混杂，还可能进入重签提示 | 账号验证不注册设备、不申请证书、不触发重装；实际续签单独初始化设备；调用边界检查 |
| 缓存登录跳过设备注册 | 先验证账号再续签时，缓存会绕过新认证路径里的注册步骤 | 缓存分支也按 skipDeviceRegistration 参数执行注册；检查两条路径 |
| 旧续签连接状态残留 | 导入新配对、修改 IP 或前次连接失败后，runtimeStarted 可能仍为真 | 每次续签先停止旧代理，再用当前配对和 IP 初始化；移除布尔缓存 |
| 格式错误会进入定位未知状态 | 传统配对/无效 IP 在本地就失败，却提前锁定为可能遗留模拟，妨碍更换文件 | 本地前检查通过后才记录发送意图；发送前仍先持久化未知状态，避免丢回复误报安全 |
| 配对导入只接受 UTF-8 文本 | 有效二进制 plist 被当作无效文件；传统/远程格式与错误设备缺少区分 | XML/二进制统一规范化，检查字段；可核对 UDID 时拒绝另一设备；格式与设备身份回归测试 |
| 远程配对的更新未保存 | 底层建隧道成功时可能更新配对，下一次仍使用旧文件 | 成功后序列化并保存变化，保存失败不发送新位置；按固定 FFI 接口与所有权约定检查 |
| WebSocket 等待没有明确上限 | 服务连接后不再响应会持续等待，或者重复握手消息不结束 | 每次收发 20 秒截止、任务取消关闭 socket、限制消息大小和握手步数；截止及取消竞态测试 |
| 收藏损坏会被视为空收藏 | 解码失败后继续添加，会覆盖原收藏文件 | 缺文件与读取/解码失败分开处理，读取失败禁止修改，原字节保留；临时文件故障测试 |
| 搜索失败覆盖已选坐标说明 | 坐标仍为旧点，界面却显示搜索失败/未找到，容易混淆当前选择 | 搜索消息单独显示，输入新关键词立即清空旧结果；检查过时任务与结果代次 |
| 原生定位失败缺少最近诊断 | 连接、提交、清除失败只留在即时界面，返回设置后难追溯 | 保存阶段与固定数值错误码，不保存账号、坐标、IP 或文件内容 |
| 证书内存快照与导入并发 | 后台读取证书状态可能与导入的钥匙串事务交错 | 活动证书快照及载入/保存/清理使用递归锁；迁移后重新加载证书 |
| 证书保存有中断窗口 | 证书和解密密码分开写入，中途进程退出可能只更新一项 | 新活动证书以单条钥匙串记录原子提交，保存前验证可解密及序列号；旧记录可迁移，兼容副本不作为新主记录 |
| 启动仍做签名/商店工作 | 打开定位页仍启动数据库和图片磁盘缓存；场景事件还发布 widget | 签名数据库及维护按需初始化，保留重装后记录恢复；移除商店场景副作用 |
| 依赖和扩展交付边界不严 | SwiftPM 分支允许自动前进；无用途 widget 占用额外扩展签名流程 | 锁定 Package.resolved 摘要并禁用自动解析；IPA 不包含 widget 扩展；实际打包检查 |
| 依赖锁存在旧覆盖副本 | 还原完整项目时，overlay 中的旧副本会覆盖根目录新依赖锁，使补丁未应用 | 统一副本；还原脚本最后以根目录依赖锁和版权说明覆盖，作为唯一构建依据 |

## 自动验证范围

旧的坐标、证书策略、登录配置、凭据迁移、到期时间和保活取消测试保留。新增临时文件损坏/超限测试、XML/二进制配对、设备身份检查、IPv4 规范化、超时执行及取消竞态、旧链接拒绝测试。构建前检查账号与设备分离、缓存注册分支、定位意图记录顺序、场景启动边界和依赖锁。

这些检查使用虚构配对字段和临时文件，不登录真实 Apple 账号，也不调用真实设备。内部审查完成后，实际通过结果另见随包的《本版内审结果.md》和对应 Actions 记录。

## 已明确的限制与剩余风险

- Apple -80045/-22421/-90010 属于认证链路返回，本轮不能证明其已消失。服务配置可读取与 Apple 允许登录是不同结果；WebSocket 有超时不代表 Apple 登录一定成功。
- 固定 StikDebug 3.1.13 的当前定位通道使用远程配对。传统 Lockdown 配对可以用于支持它的续签后端，但不能作为当前定位通道的远程配对使用；App 会事先说明，不再落入更换文件的状态锁。
- 只有传统文件包含可比对的硬件 UDID。远程配对能否用于本设备，需要底层设备握手确认，导入文件成功不能代替此确认。
- 国内 MapKit 的坐标来源、地图服务区域以及应用的定位缓存仍需设备校准。当前保留国内地图的 GCJ-02/WGS-84 转换和明确 WGS-84 输入入口，未宣称各地区地图源都已校验。
- FFI 在设备网络中断时的超时与句柄释放、系统后台挂起、定位清除是否令其他 App 更新、签名覆盖后的钥匙串/收藏保留、iPad 内存与流畅性，均无法由本次桌面内审证明。清除失败继续保留未知状态和恢复说明。
- 当前简化界面沿用已有签名身份，不新增账号切换管理。更换签名身份需同时考虑证书私钥和安装数据访问，不能通过换系统 App Store 账号代替。

后续如进行真机验收，应按问题阶段记录实际错误；本轮不要求用户连接设备。
