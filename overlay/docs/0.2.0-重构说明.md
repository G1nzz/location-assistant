# 定位助手 0.2.0（4）：重构与验证边界

保留原方案：中文原生 iPhone/iPad App、StikDebug 定位模块、SideStore 自身续签、独立 LocalDevVPN。固定上游提交、许可证、应用标识和本机数据键名，便于从旧版覆盖更新。没有转为网页方案。

## 本次代码变化

- 启动页直接显示定位界面，不等待签名数据库，不自动查询软件源或探测 JIT。定位操作不要求 Apple 签名账号登录。
- 续签由独立协调器管理；登录失败和刷新进度仅显示在续签页，不再覆盖定位状态。需要登录或续签时才启动对应设备连接。
- 到期时间读取当前运行安装包的 embedded.mobileprovision；读取失败显示未知，不用旧数据库日期代替。
- 清除模拟前取消已排队的 iOS 26 保活任务，避免旧任务在清除后再次发送位置；底层未返回有效服务句柄时不报告命令成功。
- 保留手动清除、失败后的未知状态和重启恢复确认；不自动把“停止界面”视作已恢复真实定位。
- 登录服务可从固定允许列表中明确选择；“配置可读取”和“Apple 登录成功”分别表述。保留已知 Apple 错误码，识别包装在通用错误 21 里的认证失败。
- 账号、私钥、配对和收藏仍留在设备本地，不进入公开仓库或构建任务。不会自动撤销账号的已有签名证书。

## 尚未解决的外部限制

重写 App 不能保证修复 Apple GrandSlam/Anisette 登录失败。当前用户提供的 iloader 2.3.9 日志已经出现过 HTTP 502、WebSocket 中断、-22421、-90010 和 -80045；这些发生在安装工具或认证链路，不能以本项目编译成功作为已解决的证据。

定位功能不需要日常登录签名账号，但 App 必须具有有效安装签名。移除登录门槛不等于免签或永久有效。到期后无法启动时，仍可能需要电脑和可用的签名工具覆盖安装。

同一签名账号在多台设备使用时，需要对应证书的完整私钥；只有证书公钥文件不能续签。签名身份可以共享，配对文件不能跨设备代用。应用内不自动从另一台设备或 Apple 服务器取回私钥。

## 验证顺序

1. GitHub macOS 构建、坐标/证书策略/登录数据/钥匙串迁移/错误包装/排队保活取消测试。
2. 覆盖安装，确认版本 0.2.0（4），确认收藏和本设备配对保留。
3. 不登录签名账号，完成地图选点、开始模拟、切换苹果地图和高德验证、清除并恢复真实位置。
4. 在有效签名期限内，单独验证登录、证书私钥和自身续签。重开 App 核对安装包到期时间；失败时保留实际错误码。
5. iPhone 12 / iOS 18.6.2 与 iPad 9 / 用户提供的 iPadOS 26.6 分别记录结果。iPad 的输入、拖动、切页、后台行为与内存必须实测，未测不标通过。

本文件编写时两台设备的本版本真机验收均未进行。最终交付中的构建报告只记录实际完成的构建和检查。
